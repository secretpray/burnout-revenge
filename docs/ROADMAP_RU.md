## 0. Подготовить чистое продолжение

1. Открыть отдельный репозиторий Burnout, проверить remote/branch/status/HEAD.
   Прочитать ACTIVE_WORK, этот план и только нужные профильные документы.
   Не читать целиком многотысячную историю SpeedBreaker.
2. Сверить сборочную копию с тем же Git commit. Использовать готовые локальные
   зависимости и generated PPC при совпадении исходников; не вести две расходящиеся
   версии кода и не перетирать чужие незакоммиченные изменения.
3. Проверить фактическую версию приложения в Applications и сохранность данных.
   Перед заменой сохранить предыдущую .app; не переименовывать продукт в First Run.
4. Для запусков — изолированные data/cache и ограниченный процессом caffeinate.
   Не менять постоянные настройки блокировки macOS и не включать системную
   UI-автоматизацию/перехват клавиатуры.

**Готово, когда:** известны source hash, build hash, реальные каталоги и статус
публикации; сохранения защищены; приложение и кандидат нельзя перепутать.

## 1. Завершить исправление ввода и проверить конечный пакет

Уже исправлено в исходниках: SDL audio init на main thread; независимые gates
фокуса и suspension для каждого запроса вибрации; hide/minimize очищают локальное
состояние клавиш; restore проверяет настоящий focus; Cmd shortcuts не управляют
машиной. Эти правки не включены в установленный cda797a.

Остаётся:

1. Сохранить положительный результат 96 и не расширять его: пользователь явно
   подтвердил клавиатуру; звук и реальное управление геймпадом нужно подтвердить
   отдельно в проверке пакета. Native SDL сообщил transport=unknown — не считать
   его доказательством USB/Bluetooth. Старый v0.1.1 проваливал ручной тест 93.
2. Собрать новый **чистый кандидат** из зафиксированного кода. Тег v0.1.1 не менять;
   для нового релизного кода использовать следующий свободный patch-version
   (ожидаемо v0.1.2 после проверки списка тегов). Название/иконка/каталоги Burnout.
3. Собрать .app/DMG; проверить codesign, зависимости, macOS 15 floor/weak imports,
   скруглённую alpha-иконку, версии и hash. Подготовить точные LGPL sources и sums.
4. Сначала загрузить в GitHub draft, скачать оттуда, проверить SHA-256 и установить
   именно скачанную копию. Проверить пустой первый экран, а установку/профиль —
   изолированно, без подмены исходных пользовательских данных.
5. Ручная гонка 5–10 минут: двигатель/столкновения/музыка, реальный геймпад и печать
   после обоих направлений Cmd+Tab (несколько циклов), Cmd+H/restore, обычный выход
   и повторный запуск. USB и Bluetooth — отдельные строки результатов.
6. Если отказ повторится — остановить публикацию и применить SDL probe из
   INPUT_DIAGNOSTICS.md: none → native → audio → explicit rumble; raw только как
   сравнительный вариант. Отдельно проверить windowed/fullscreen; Game Mode
   рассматривается как гипотеза, а не установленная причина.
7. После прохождения — новый публичный release/Latest, актуальные release notes и
   ссылка из старого релиза. Не удалять старые теги/артефакты и не публиковать dSYM,
   ISO, saves, raw Bluetooth logs или generated PPC sources.

**Критерий:** совпадающие байты проверенного скачанного пакета; положительная ручная
проверка keyboard/controller/audio; полные релевантные тесты; честные ограничения
в release notes. Утверждение «100% на всех Mac» недопустимо. Ad-hoc не означает notarized.

## 2. Проверить возможность родного игрового экрана имени

Требование пользователя условное: заменить только если это действительно точнее
оригинала. Системная панель Xbox 360 не является желаемой целью. Сейчас остаётся
наша клавиатура; в Xerenge нет готовой родной замены.

1. По NATIVE_KEYBOARD_RU.md разобрать APT actions и связи KeyboardShow/Move/Type/Back,
   m_bHiKeyboard. Отделить живой игровой путь от мостика XAM/неиспользуемого остатка.
2. Если полный путь найден — отдельный эксперимент с игровыми ресурсами из ISO.
   Не добавлять NFSMW assets или консольный dashboard в дистрибутив.
3. Сравнить вид и поведение: навигация, ввод, case/delete/space, accept/cancel,
   длина/Unicode, многократное открытие, потеря фокуса, сохранение и reload.
4. Если путь неполный — документировать и оставить текущий диалог. Полнота flags,
   UTF-16 boundaries, busy/cancel/overlapped completion проверяется отдельно от скина.

**Критерий:** реальный игровой экран и корректный контракт вызова, либо явное
решение «не заменять». Не блокировать все остальные работы бесконечным reverse engineering.

## 3. Опциональная предварительная подготовка графики

**Статус 18.10.2026: отложено по замеру** — [SHADER_PREP_BASELINE](SHADER_PREP_BASELINE.md).

Самая практичная следующая performance-функция из внешних проектов. Не обещает
повысить средний FPS: цель — первые shader/pipeline hitches.

1. Измерить холодный старт и первую гонку/Crash без снимков во время замера:
   p50/p95/p99 frame time, compile misses, общее время подготовки, GPU timestamps.
2. Добавить покрытие shader/PSO и reviewed metadata-only manifest для USA build.
   Отдельно учитывать static shaders и программы, которые игра собирает на лету.
3. Реконструировать микрокод из verified пользовательских файлов, сверять hashes.
   Идея Xerenge recipe переносима, но её hash/translator/EU-US coverage не совпадают
   автоматически с нашим renderer. Не распространять чужой driver cache.
4. Прогревать реальные Vulkan pipelines, включая layout/topology/formats/blend/depth,
   а не только SPIR-V modules. Сохранить совместимость cache по схеме, translator,
   GPU/driver/game build. Повреждённый/чужой cache безопасно пересоздавать.
5. Прогресс/cancel/resume, ограниченные workers, обычный first-use fallback.
   Подготовка не должна проходить гонки на пользовательском save.
6. Только после рабочего backend — опция Prepare graphics при установке и в Settings.
   Реальные счётчики, простое объяснение пользы; UI не загромождать.
7. Повторить одинаковые race/Crash/menu cold vs prepared vs warm restart.

**Критерий:** заметное уменьшение хвостов frame time и compile misses на проверенном
наборе; корректная отмена/повторный старт; неизменные saves и отсутствие чужих caches.

## 4. Улучшить изображение с измерениями

**Статус 18.10.2026: выполнено** — SMAA по умолчанию; CAS и bloom решены замером ([IMAGE_QUALITY](IMAGE_QUALITY.md)). Motion blur — сделан (v0.1.9/0.1.11); LOD и дальность прорисовки — этап 8, шаг 1.

1. Добавить SMAA 1x из официальной MIT-реализации как альтернативу FXAA;
   проверить lookup textures, три passes, цветовое пространство и границы 16:9/HUD.
2. Сравнить CAS с существующими sharpening/FSR RCAS. Не добавлять дублирующий slider
   только ради названия: нужны преимущества по halo, мелким деталям и GPU времени.
3. Проверить bloom/downsample taps при 1080p. В Plume у Xerenge была причина shimmer,
   связанная с 720p taps на более крупном target; наш resolve path нужно проверить
   самостоятельно. Полное отключение bloom меняет яркость неба и облик игры.
4. Затем рассмотреть LOD, distant detail, motion blur controls по подтверждённым USA
   функциям. Нельзя просто записать Xenia PPC byte patch в статически собранный код.
5. Одни scene/camera/resolution: lossless crops, HUD, FPS и реальное GPU execution
   time. При выключенных timestamps поле «0 ms» не является замером стоимости.

**Критерий:** улучшение видно на одинаковой сцене, бюджет M1 Pro измерен, старый режим
доступен. Пока базовая рекомендация: внутренние 1080p/Bicubic/AA, sharpen ~0.3, AF16;
при нехватке GPU — 720p. Это отправная точка, а не универсальный preset для всех Mac.

## 5. Довести интерполяцию кадров до полезного режима

У нас уже подготовлены depth/motion/HUD и GPU history; live FG не включена.

1. Зафиксировать source frame IDs/epochs, cut/resize/menu/loading invalidation,
   полноту depth/HUD, корректность движения машин и дороги на нескольких трассах.
2. Реализовать history leases/events и безопасный Vulkan/MoltenVK → Metal consumer:
   lifetime, producer/consumer synchronization, resize/reclaim, bounded memory.
3. Подключить MetalFX FI отдельным developer-режимом: правильные timestamps,
   reset history и гарантированный fallback на настоящий кадр при неполных входах.
4. Сравнить с **собственной** draw-state interpolation по подходу Xerenge:
   match по pass/target/shader/buffers/index range, уникальность одинакового traffic,
   camera cuts, HUD/particles/reflections/skinning. Plume-файл не drop-in к нам.
5. Сначала Crash 30→60 на 60 Hz; затем race 60→120 на настоящем 120 Hz дисплее.
   Учесть добавочную задержку метода с двумя готовыми кадрами и CPU/GPU цену re-render.
6. Проверить реальные разные показанные кадры, pacing, physics/music speed, input
   latency, ghosting/disocclusion/HUD, p95/p99 и память. Счётчик duplicated presents
   или снятый FPS cap не считается работающей FG.
7. В пользовательские Settings включать только после сравнения и устойчивого fallback.

**Критерий:** плавность лучше, артефакты/задержка и стоимость приемлемы и измерены.
Нет обещания 144 FPS на M1. DLSS не появляется от переименования алгоритма.

Локальная копия `speedbreaker` (ветка `main`) следует за upstream; наша работа — в своей ветке
и в этом репозитории. Каждый релиз upstream разбирать по Mac-полезности:

  фиксированной частотой, не для ProMotion: перенести (ACTIVE_WORK).

## Порядок тестов и документации

После каждого запуска сразу записывать: номер/дата, source/build/version/hash,
какой executable реально запущен, data/cache/env overrides, physical/virtual input,
длительность и завершение, достигнутый экран, ошибки/imports, что увидели в capture
и что подтвердил пользователь. Не смешивать эти два типа доказательств.

Повторять тесты после смысловых изменений; не гонять все suites снова ради docs.
VM/Metal-тестам нужен соответствующий доступ. Чувствительные timing/stress тесты
прогонять без одновременной тяжёлой сборки; не ослаблять assertions ради прохода.
Raw logs, screenshots, saves, ISO, decrypted images и generated PPC — приватные
build artifacts. В публичный source идут код, метаданные, инструкции и честная сводка.
