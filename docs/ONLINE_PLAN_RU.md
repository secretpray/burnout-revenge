## Где мы сейчас

- Сеть — «честная консоль без кабеля» (v0.1.12): `kernel/burnout_imports.cpp` даёт настоящие
  BSD-сокеты, но привязанные к loopback; XNet-адрес «нет», DNS/QoS ничего не находят,
  connect не проходит. Xbox Live в меню отвечает «нет соединения» и возвращает в меню.
- Live-службы игра зовёт не импортами, а сообщениями XMsg приложениям XGI (0xFB) и
  XLiveBase (0xFC) — у нас они сейчас все `X_E_FAIL` (`kernel/xmsg.cpp`). Адрес лобби игра
  берёт так же: XOnlineGetServiceInfo для службы 0x45410004.
- Заглушки, которые понадобятся онлайну: XamSessionCreateHandle/RefObjByHandle,
  XamUserAreUsersFriends, XamShowFriendsUI/GamerCardUIForXUID/MessageComposeUI,
  XamParseGamerTileKey/ReadTileToTexture. `XamUserGetSigninState` отвечает «вошёл локально».
- Голос: XamVoice* есть; гарнитуры нет — онлайн с голосом не делаем.

## Как это устроено у Xerenge (факты)

1. **SDK-половина**: консоль отвечает «вошёл в Live, соединение есть»; XOnlineGetServiceInfo
   (0x45410004) отдаёт адрес сервера лобби; XNADDR несёт LAN-адрес; сокеты привязываются к
   нему; XSESSION_INFO заполняется для хоста. Этого достаточно, чтобы DirtySock EA сказал
   `onln`.
2. **Половина игры** (~80 хуков): машина состояний входа `CB4XenonLoginMenuState` (+0x140):
   0 ролик меню → 1 сетевой менеджер → 2 игроки → 3 сетевое лобби → 4 выбор геймертега →
   5 Live (`onln`) → 6 соединение с лобби → 7 вход в лобби → 8 условия использования →
   10 конфигурация → 11 готово/ошибка. Пропуски: Revenge Rivals, новости и условия (без
   ответа сервера падают), защита VoipGetRef = null, обрыв соединения, создание сессии
   `sess` (0x8240C908: хост, если XUID хоста ref+0x70 = свой ref+0x80), проверки «меня
   выгнали» (0x82366CF8) и «у комнаты есть хост» (0x82366F78), маршрут 3+ игроков: порты
   8192/6000 — напрямую игроку, только 31859–31861 — лобби.
3. **Сервер `ealobby`** (C++17, ~2200 строк): протокол Aries — заголовок 12 байт (команда
   4 символа, код 4 символа, длина big-endian) + текст `KEY=VALUE`, NUL в конце. Сначала
   каталог `@dir` на TCP 31860, затем лобби (31861). Команды, которые игра шлёт: `@dir @tic
   addr skey news acct auth pers user sele onln cate mesg snap sdta sviw ~png`, игры `gcre
   gjoi gjnf gsea gset gsta glea gdel gqwk`; сервер шлёт `+who +mgm +msg +gam +ses +snp`.
   ID игрока — FNV-1a от геймертега (положительный, не 0). Неизвестная команда — пустой успех
   и строка в журнале. Связь серверов LAN: `xhlo xjoi xfwd xlea`, анонсы по UDP 31859
   (broadcast + multicast). Клипы: EA Locker по HTTP на 31862.
4. Топология: каждая копия поднимает своё лобби и находит соседей по LAN, игру несёт лобби
   хоста («seamless multiplayer»); или `--lobby_server=<host>` — один общий сервер (дом, VPS).
   Две копии на одной машине — адреса 127.0.0.2 и 127.0.0.3.

**Проверка адресов на нашей USA-сборке** (19.10, выборочно): все 95 функций, которые
перехватывает Xerenge, у нас есть как начала функций; в 0x82366CF8 те же смещения (имя
+4248, счётчик +556, шаг 140), в 0x8240C908 чтение ref+0x70. Xerenge с 0.4.7 официально
поддерживает и USA. Каждый хук всё равно сверяем по нашему дизассемблеру перед использованием.

## Фазы

Каждая фаза — отдельная ветка/коммиты, своё «готово», тесты и прогоны в папке validation.
Всё онлайн-поведение — за настройкой **Settings > Online** (по умолчанию выключено), так что
офлайн-игра не меняется.

### Фаза 0. Разведка с журналом (1–2 дня)
- `BURNOUT_ONLINE=1` (временно env): `XamUserGetSigninState` = вошёл в Live, XUID с
  онлайн-битом, привилегия мультиплеера; журнал всех XMsg 0xFB/0xFC (номер сообщения,
  буфер); журнал смен состояния входа (+0x140) — хук на чтение/запись по адресу из
  дизассемблера USA.
- Готово: прогон «Xbox Live» в меню показывает, на каком состоянии и каком сообщении вход
  встаёт; список сообщений XLiveBase, нужных игре.

### Фаза 1. SDK-половина: «Live подключён» (≈1 неделя)
- XNet: ссылка есть, XNADDR с LAN-адресом (выбранный интерфейс или 127.0.0.x), XnAddr↔InAddr,
  ключи, QoS-ответы для настоящих пиров; сокеты привязываются к этому адресу, а не к loopback.
- XLiveBase: XOnlineGetServiceInfo(0x45410004) → адрес лобби; остальное из фазы 0.
- XamSession*: дескрипторы сессий, XSESSION_INFO хоста. Голос: гарнитуры нет.
- DNS: имена EA не резолвим никогда — только наш сервер (никаких обращений к внешним хостам).
- Тесты: XNADDR/сессии в юнит-тестах (без игры).
- Готово: вход доходит до состояния 6 («соединение с лобби»), DirtySock `onln`.

### Фаза 2. Свой сервер лобби, вход (≈1–1,5 недели)
- Сначала — вход на **сервер автора** (если он согласен): клиентская часть проверяется на
  настоящем сервере, свой сервер сверяется с ним по стенограммам.
- Библиотека `net/aries.*` (кодек + поля) и `net/lobby_server.*`: каталог `@dir`, вход
  (`addr skey auth acct pers user sele onln`), пустые `news`/`cate`/`snap`, пинги `~png`.
  Поток внутри игры + та же библиотека как отдельная утилита `tools/burnout-lobby` (для VPS).
- Тесты: кодек Aries, разбор полей, воспроизведение записанной сессии входа.
- Готово: вход доходит до 11, открываются онлайн-меню; 30 мин простоя без обрыва и заглушек.

### Фаза 3. Хуки входа на стороне игры (2–4 дня)
- Пропуск Revenge Rivals, новостей и условий; защита VoipGetRef; обработка обрыва связи
  (возврат в меню, а не падение). Каждый адрес — сверка с нашим дизассемблером.
- Готово: вход/выход из онлайна 10 раз подряд, Quit Game из онлайн-меню, без hang-отчётов.

### Фаза 4. Игра на двоих (≈1–2 недели)
- Сервер: `gcre gjoi gjnf gsea gset gsta glea gdel gqwk`, рассылки `+mgm +who +gam +ses`;
  игра: создание сессии `sess` (хост/присоединившийся, отказ вместо падения при пустом
  указателе), «выгнан»/«нет хоста» с журналом.
- Готово: две копии на одном Mac (127.0.0.2/3) или два Mac — создать комнату, найти её,
  гонка Race и Road Rage до результатов, повтор, выход хоста посреди гонки.

### Фаза 5. 3+ игроков, LAN без сервера, интернет (≈1 неделя)
- Маршрут пиров: 8192/6000 — напрямую игроку, 31859–31861 — лобби. Анонсы UDP 31859 и связь
  лобби (`xhlo xjoi xfwd xlea`) — игра по LAN без отдельного сервера.
- Интернет — только через свой сервер на VPS (проброс портов/NAT — в документации); P2P через
  NAT не обещаем.
- Готово: 3 копии (третья — второй Mac или Linux), Crash Party/Crash Battle онлайн.

### Фаза 6. Burnout Clips онлайн (по желанию, ≈1 неделя)
- EA Locker по HTTP на 31862: загрузка, Top 20/последние игроки, файлы на сервере.
- Готово: клип одного игрока виден и играет у другого.

### Фаза 7. Продукт и релиз (2–3 дня)
- Settings > Online: вкл/выкл; сервер: «Xerenge (shipa-2)» (если автор согласен), «Свой»
  (адрес/порт), «LAN без сервера»; имя = геймертег профиля; кнопка «Проверить» (запрос
  `@dir` с таймаутом и понятной ошибкой). Наш клиент помечает себя (поле, согласованное с
  автором), чтобы автор мог отличать и ограничивать его.
- macOS Firewall: входящие соединения спросят разрешение (ad-hoc подпись может спрашивать
  после каждого обновления) — проверить и описать в README.
- README/CHANGELOG, атрибуция Xerenge (идеи, адреса, протокол) и ReXGlue/Xenia (если
  возьмём файлы SDK), `docs/` с портами и запуском сервера.

Итого 5–8 недель работы сессиями; фазы 0–3 дают «онлайн-меню без игр», 4 — первую
игру на двоих.

## Как проверять

- На одном Mac: по умолчанию в macOS есть только 127.0.0.1 — для 127.0.0.2/3 нужен
  `sudo ifconfig lo0 alias 127.0.0.2` (делает пользователь; до перезагрузки). Альтернатива —
  второй порт на 127.0.0.1, если игра это позволит (проверить в фазе 1).
- Два Mac в одной сети — лучший тест LAN; третья копия — для фазы 5.
- Совместимость с Xerenge (если решим её держать): прогон против их `ealobby` на Linux/
  Windows-машине или в VM.
- Каждый прогон: журнал сети (`BURNOUT_LOG_NET=1`), состояния входа, кадры меню и гонки,
  ручная игра пользователя на двух устройствах для фаз 4–5.

## Риски

- Адреса хуков USA: проверены выборочно; несовпадение даёт тихо неверное поведение —
  каждый хук сверяется до использования.
- Протокол знаем только по Xerenge: сервер отвечает на всё, что игра шлёт, а неизвестное
  пишет в журнал (как у них), чтобы каждый прогон показывал следующий шаг.
- Брандмауэр macOS, NAT, открытые порты: по умолчанию сервер слушает только LAN/loopback.
- Безопасность: сервер ничего не исполняет из сообщений, лимиты на размер/число соединений,
  разбор строк без доверия к данным.
- Версии Xerenge дрейфуют: совместимость — по зафиксированному снимку протокола и тесту.
